# GBrain並行検索の実験（20261117ブランチ）

## 動作

`--search parallel`でBM25とGBrainを同時に開始する。GBrainは最大2.5秒だけ待つ。
間に合った結果は既存の順位融合処理へ渡し、間に合わない・利用できない・対応文書がない
場合はBM25だけの結果を返す。既定の検索方式はkeywordのまま。

- 新しい外部ライブラリの追加なし
- GBrainの同時実行はプロセス内で1件まで。使用中はBM25へ即時切り替え
- GBrainのWindowsプロセスを時間切れで止める際は、子プロセスも終了
- 遅い検索処理を待つためにリクエスト全体を止めない
- Slackの回答待機上限16秒を維持し、回答生成の時間を確保
- GBrain未インストール、索引・キー未設定でもparallelはBM25へ切り替える
- GBrainの既存質問キャッシュを利用。資料・質問・件数が変わると別のキャッシュになる

## 実測

### 固定20問

既存のローカルMD（46ファイル）と、その文書を対象にしたGBrain索引を使用した。
質問前処理は相談判定も含めて本番の検索経路に合わせた。
先頭4問は事前に質問キャッシュを作成した状態で、残りは検索時にGBrainを実行した。

| 指標 | BM25 | 並行検索 |
| --- | --- | --- |
| 正解ファイルTop-1 | 18/20（90%） | 18/20（90%） |
| 正解ファイルTop-5 | 20/20（100%） | 20/20（100%） |
| 必要根拠Top-1 | 17/20（85%） | 18/20（90%） |
| 必要根拠Top-5 | 19/20（95%） | 20/20（100%） |

GBrain結果を統合できたのは19/20問。1問は時間切れでBM25へ切り替えた。
キャッシュ済みの並行検索は約0.30〜0.33秒、未キャッシュの検索は約2.27〜2.53秒。
スレッド切り替え等のため、関数の実時間は2.5秒をわずかに超えることがある。
先行して行った初回4問の試験ではGBrainが時間切れとなり、終了処理中の連続質問は
busyとしてBM25のみを返した。19/20という結果は完全なコールド状態の成功率ではない。

### 現在のDrive dataを使った相談2問

24ファイル・473チャンクを起動時に読み込み、Flash-Liteで最終回答を生成した。

| 相談 | 回答処理全体 | 回答生成時のGBrain結果 |
| --- | --- | --- |
| 経理採用を上手く行かせるには | 6.078秒 | no_match（対応する根拠なし） |
| エンジニアの選考フローどうしたら | 6.594秒 | no_match（対応する根拠なし） |

両方とも根拠付き回答を生成でき、時間切れはなかった。Slackの受信・投稿通信は含まない。
ただし両方ともBM25のみで回答しており、現在のDrive資料に対するGBrainの精度改善を
確認したものではない。既存索引を再利用した実験のため、索引対象と現在の資料の
対応確認・必要に応じた索引更新が次の課題。古い索引を現在の資料に強引に結び付けない。

## 実行

GBrainのインストール・索引・Gemini認証が必要。索引の場所が既定と異なる場合は
`GBRAIN_HOME`を設定する。公開リポジトリには索引、キャッシュ、会議原文、認証情報を含めない。

```powershell
cd "Hermes Agent型"
$env:GBRAIN_HOME="C:\任意の場所\既存のGBrain索引"
$env:GEMINI_API_KEY="取得したキー"

python .\hermes_agent.py "質問文" --provider gemini --search parallel
python .\slack_bot.py --search parallel
```

質問キャッシュなしと事前作成ありを比較する場合:

```powershell
python .\benchmark_parallel.py --docs-dir "C:\会議ログ" `
  --questions "C:\評価質問.json" --count 20

python .\benchmark_parallel.py --docs-dir "C:\会議ログ" `
  --questions "C:\評価質問.json" --count 4 --prime
```

相談の実API検証は`--api`で有効にする。GBrain検索も質問EmbeddingのAPIを使う。
`--prime`は各質問を最大30秒待ち、評価対象の2.5秒制限とは別にキャッシュを準備する。
無料枠や料金はAPIプロジェクトの設定に依存する。

## 検証範囲

59件の単体テストが成功。並行開始、時間切れ、未インストール・エラー時の切り替え、
busy時の追加処理抑制、ゼロ秒予算、Windowsの子プロセス終了を検証した。
機密の評価質問・原文はローカルだけで使用し、リポジトリには含めていない。

mainブランチと稼働中のSlack Botは変更していない。現時点では、現在のDrive資料への
対応確認が終わるまで本番の既定方式をparallelへ切り替えない。
